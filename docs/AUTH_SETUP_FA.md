# راه‌اندازی احراز هویت بازارچه

این تغییر، ورود با شماره موبایل و رمز عبور و ثبت‌نام فقط با دعوت‌نامه را اضافه می‌کند. کد دعوت فقط یک‌بار مصرف است و متن آن پس از صدور فقط همان یک‌بار نمایش داده می‌شود.

## ۱) Migration

پس از ادغام تغییرات در `main`، Workflow مربوط به `Apply D1 Migrations` را اجرا کنید و `apply_migrations=true` بگذارید. Migration جدید `0002_invitation_auth.sql` است. فایل `0001_initial.sql` نباید ویرایش یا دوباره اجرا شود.

## ۲) Secrets مورد نیاز Worker

در Cloudflare Worker > Settings > Variables and Secrets این Secretها را تعریف کنید:

- `SESSION_SECRET`: یک مقدار تصادفی حداقل ۳۲ نویسه‌ای؛ برای HMAC شناسه نشست، کد دعوت و کلیدهای محدودیت درخواست. تغییر این Secret نشست‌های قبلی و دعوت‌نامه‌های صادرشده ولی مصرف‌نشده را نامعتبر می‌کند.
- `BOOTSTRAP_ADMIN_SECRET`: یک مقدار تصادفی حداقل ۳۲ نویسه‌ای؛ فقط برای ایجاد اولین مدیر.

برای ساخت مقادیر تصادفی می‌توانید از این دستور محلی استفاده کنید:

```bash
openssl rand -base64 48
```

خروجی را برای هر Secret جداگانه بسازید. این مقادیر را در GitHub، کد Frontend یا فایل `wrangler.toml` قرار ندهید.

## ۳) ساخت اولین مدیر

پس از Deploy و تنظیم Secretها، یک بار درخواست زیر را با ابزار امنی مانند curl اجرا کنید. مقدار Bearer باید همان `BOOTSTRAP_ADMIN_SECRET` باشد:

```bash
curl -X POST 'https://YOUR-WORKER-DOMAIN/api/admin/bootstrap' \
  -H 'Authorization: Bearer YOUR_BOOTSTRAP_ADMIN_SECRET' \
  -H 'Content-Type: application/json' \
  --data '{
    "phone": "09123456789",
    "password": "REPLACE_WITH_A_LONG_UNIQUE_PASSWORD",
    "display_name": "مدیر بازارچه",
    "city_code": "TEH",
    "city_name": "تهران"
  }'
```

شماره و رمز نمونه بالا را با اطلاعات واقعی مدیر جایگزین کنید. بعد از دریافت پاسخ موفق، Secret با نام `BOOTSTRAP_ADMIN_SECRET` را فوراً از Worker حذف کنید. این مسیر پس از ساخته‌شدن اولین مدیر، دیگر اجازه ساخت مدیر اولیه نمی‌دهد.

## ۴) صدور کد دعوت

مدیر پس از ورود باید به `POST /api/admin/invitations` درخواست بدهد:

```json
{
  "role": "buyer",
  "expires_in_hours": 168
}
```

برای دعوت فروشنده، `role` را `seller` بگذارید. مدت اعتبار بین ۱ تا ۷۲۰ ساعت است. کد دعوت در پاسخ فقط یک بار برگردانده می‌شود؛ آن را از طریق کانال امن به شخص موردنظر بدهید.

## ۵) APIهای احراز هویت

- `POST /api/auth/register`: `phone`, `password`, `display_name`, `city_code`, `city_name`, `invitation_code`
- `POST /api/auth/login`: `phone`, `password`
- `GET /api/auth/me`: دریافت کاربر نشست فعلی
- `POST /api/auth/logout`: ابطال نشست فعلی
- `POST /api/admin/invitations`: صدور دعوت‌نامه، فقط مدیر
- `POST /api/admin/bootstrap`: ایجاد مدیر اولیه، فقط یک بار و با Secret راه‌اندازی

شماره‌های موبایل فارسی، عربی، `09...` و قالب بین‌المللی `+98...` پذیرفته و به قالب `09xxxxxxxxx` تبدیل می‌شوند. رمز عبور باید حداقل ۱۲ و حداکثر ۱۲۸ نویسه باشد.

## ۶) نکات امنیتی و محدودیت دامنه این مرحله

- رمز عبور با PBKDF2-HMAC-SHA256 و salt تصادفی هش می‌شود؛ متن رمز ذخیره نمی‌شود.
- نشست در کوکی `HttpOnly`, `Secure`, `SameSite=Strict` و با پیشوند `__Host-` نگهداری می‌شود؛ توکن خام نشست در D1 ذخیره نمی‌شود.
- ورود و ثبت‌نام دارای محدودیت درخواست مبتنی بر D1 هستند. برای بار زیاد، بهتر است بعداً Cloudflare Rate Limiting یا binding اختصاصی هم اضافه شود.
- درخواست‌های تغییردهنده بین‌سایتی رد می‌شوند و CORS عمومی `*` حذف شده است. رابط باید از همان دامنه Worker استفاده کند.
- نقش دعوت‌نامه فقط `buyer` یا `seller` است؛ دعوت‌نامه نمی‌تواند مدیر بسازد.
- ثبت‌نام با دعوت معتبر حساب را فعال می‌کند. تأیید هویت اشخاص، بازیابی رمز، تغییر شماره، MFA و مدیریت کاربران هنوز در این مرحله پیاده‌سازی نشده‌اند.
- این مرحله احراز هویت را اضافه می‌کند، نه کل API محصولات و سفارش‌ها. قبل از فعال‌کردن خرید واقعی، مجوزدهی هر endpoint و جریان سفارش باید جداگانه تکمیل و تست شود.

## ۷) اتصال فرم ورود به صفحه فعلی

فایل `public/auth-ui.js` یک پنجره ورود/ثبت‌نام فارسی به صفحه فعلی اضافه می‌کند و دکمه `ورود اعضا` موجود را به API متصل می‌کند. در `public/index.html`، درست بعد از خط فعلی زیر:

```html
<script src="./app.js"></script>
```

این خط را اضافه کنید:

```html
<script src="./auth-ui.js"></script>
```

فایل `public/index.html.patch` نیز همین تغییر کوچک را به‌صورت patch نشان می‌دهد. اسکریپت احراز هویت بعد از `app.js` بارگذاری می‌شود تا رفتار نمایشی قبلی دکمه ورود را جایگزین کند.
