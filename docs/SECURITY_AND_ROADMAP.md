# امنیت و نقشه تکمیل

## قبل از استفاده واقعی (مسدودکننده انتشار)
- پیاده‌سازی احراز هویت با هش رمز عبور امن (Argon2id یا PBKDF2 با پارامترهای به‌روز)، نشست امن، کوکی HttpOnly/Secure/SameSite و انقضای نشست.
- مصرف اتمیک دعوت‌نامه و جلوگیری از استفاده مجدد؛ محدودیت نرخ برای ورود و ثبت‌نام.
- کنترل دسترسی سمت سرور در تمام endpointها؛ مخفی کردن دکمه در UI کنترل دسترسی محسوب نمی‌شود.
- اعتبارسنجی نوع/اندازه/محتوای فایل رسید؛ ذخیره در bucket خصوصی Supabase Storage و ارائه فقط با signed URL کوتاه‌عمر.
- جلوگیری از XSS، CSRF، IDOR، SQL injection و آپلود فایل مخرب.
- محدودیت قیمت/موجودی، رزرو اتمیک موجودی هنگام سفارش و جلوگیری از سفارش تکراری.
- ثبت audit log برای تغییر قیمت، موجودی، تأیید پرداخت و تغییر وضعیت سفارش.
- عدم نگهداری اطلاعات کامل کارت بانکی در دیتابیس؛ فقط اطلاعات لازم و با رضایت فروشنده.
- سیاست حفظ داده، حذف رسیدها، رسیدگی به شکایت و شرایط استفاده.
- پشتیبان‌گیری و آزمون بازیابی D1.

## مراحل اجرایی
### مرحله 1 — نمونه رابط (این بسته)
- مرور محصولات، جستجو، فیلتر شهر/دسته، نمایش قیمت و فروشنده
- فرم نمایشی افزودن محصول
- جریان نمایشی سفارش و بارگذاری رسید (بدون ارسال واقعی)

### مرحله 2 — API و داده واقعی
- عضویت دعوت‌محور، نقش‌ها، پروفایل و شهرها
- CRUD محصول، وضعیت تأیید، تصاویر محصول
- سفارش‌های جداگانه برای هر فروشنده و کنترل موجودی
- نمایش اطلاعات پرداخت فقط به خریدار سفارش

### مرحله 3 — پرداخت و تحویل
- بارگذاری امن رسید، اعلان فروشنده
- تأیید دستی پرداخت توسط فروشنده
- وضعیت‌های سفارش و ثبت زمان/محل تحویل حضوری

### مرحله 4 — مدیریت و انتشار
- پنل مدیریت، گزارش و audit log
- تست امنیت، تست موبایل، دسترس‌پذیری و تست همزمانی
- استقرار آزمایشی و سپس انتشار محدود

## تصمیم‌های باز برای قبل از انتشار
- نام و هویت بصری نهایی بازارچه
- روش دعوت: کد دعوت یک‌بارمصرف یا لینک دعوت
- چه کسی فروشنده را تأیید می‌کند؟
- نمایش شماره کارت یا شبا؛ توصیه: انتخاب فروشنده و نمایش فقط در سفارش
- سیاست لغو، استرداد و اختلاف


## اتصال Supabase Storage (بدون R2)
- Bucket `product-images`: فقط تصاویر عمومی محصول؛ هیچ رسید یا مدرک پرداختی در این bucket قرار نگیرد.
- Bucket `payment-receipts`: خصوصی؛ دانلود فقط پس از احراز هویت و بررسی اینکه کاربر خریدار همان سفارش یا فروشنده همان سفارش یا مدیر مجاز است.
- Worker با `SUPABASE_URL` و Secret با نام `SUPABASE_SERVICE_ROLE_KEY` درخواست‌های مدیریتی Storage را انجام می‌دهد.
- مرورگر هرگز `service_role` را دریافت نمی‌کند. برای بارگذاری، Worker پس از احراز هویت و بررسی مالکیت سفارش، signed upload URL صادر می‌کند (توکن بارگذاری طبق مستندات Supabase تا ۲ ساعت معتبر است)؛ مسیر فایل باید تصادفی و غیرقابل حدس باشد و پس از بارگذاری فوراً به سفارش متصل شود.
- پس از آپلود، Worker باید object path را به سفارش متصل کند؛ به نام فایل یا مسیر ارسالی کلاینت اعتماد نشود.
- برای رسیدها signed download URL کوتاه‌عمر صادر شود. URL عمومی برای رسید ممنوع است.
- سقف فایل و MIME type در تنظیمات bucket و دوباره در API کنترل شود.
- Free plan طبق مستندات فعلی 1 GB فایل و 5 GB egress دارد؛ پروژه‌های رایگان در صورت یک هفته عدم فعالیت ممکن است pause شوند. پیش از اتکا در محیط عملیاتی، سهمیه و وضعیت حساب را بررسی کنید.
